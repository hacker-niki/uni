**Файл:** `frontend/src/components/ProtectedRoute.jsx`

Компонент для защиты маршрутов от неавторизованных пользователей:

```javascript
function ProtectedRoute({ children }) {
  const { isAuthenticated, loading } = useAuth()

  if (loading) return <div>Загрузка...</div>
  if (!isAuthenticated) return <Navigate to="/login" replace />

  return children
}
```

## Как работает авторизация

### 1. Вход в систему

1. Пользователь открывает http://localhost:3000
2. Если не авторизован → редирект на `/login`
3. Вводит email или выбирает тестового пользователя
4. Frontend отправляет POST запрос на `/api/auth/login`
5. Backend возвращает токен и данные пользователя
6. Токен сохраняется в localStorage
7. Редирект на главную страницу

### 2. Проверка авторизации

1. При загрузке приложения проверяется наличие токена в localStorage
2. Если токен есть → запрос на `/api/auth/me` для получения данных пользователя
3. Если запрос успешен → пользователь авторизован
4. Если ошибка → токен удаляется, редирект на `/login`

### 3. Защита маршрутов

Все маршруты кроме `/login` защищены компонентом `ProtectedRoute`:
- Проверяет флаг `isAuthenticated`
- Если `false` → редирект на `/login`
- Если `true` → показывает запрошенную страницу

### 4. Добавление токена к запросам

Axios interceptor автоматически добавляет токен ко всем запросам:

```javascript
axios.defaults.headers.common['Authorization'] = `Bearer ${token}`
```

### 5. Выход из системы

1. Пользователь нажимает кнопку "Выйти"
2. Вызывается `logout()`
3. Удаляется токен из localStorage
4. Очищается состояние пользователя
5. Редирект на `/login`

## API Endpoints

### POST /api/auth/login

**Запрос:**
```json

  "email": "admin@testgen.com"
}
```

**Ответ:**

## Особенности MVP версии

⚠️ **Это упрощенная версия для MVP:**

1. **Авторизация только по email** (без пароля)
   - В production версии будет проверка пароля

2. **Простой формат токена** (user_ID_EMAIL)
   - В production версии будет JWT токен

3. **Токен в localStorage**
   - В production версии можно использовать httpOnly cookies

4. **Без refresh токенов**
   - В production версии нужен механизм обновления токенов
